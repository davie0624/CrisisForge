## Objective

Create a reproducible, leakage-aware daily panel for the first CrisisForge
experiments, with local source snapshots, provenance metadata, chronological
splits, and a hard distinction between model inputs and validation-only labels.

## Initial design and failed decision

The first implementation used:

- adjusted ETF history from Yahoo's undocumented chart endpoint; and
- macro/market histories from FRED's keyless graph CSV endpoint.

The code and unit tests worked technically. The integration run was deliberately
stopped before FRED data were written after reviewing the current FRED Terms of
Use. Those terms prohibit using FRED Services or Content in developing or training
software, machine-learning systems, deep-learning systems, or generative AI.

This is recorded as a **failed data-governance decision**, not hidden as cleanup.
A downloadable series is not automatically permissible research training data.
No FRED/ALFRED series remains in the catalog, provider code, raw cache, or model
matrix.

The generated Yahoo cache was also removed from the deliverable because the
undocumented endpoint does not provide the archival and reuse clarity required for
the default research track.

## Adopted design at that time — superseded

> The Cboe inputs and dimensions in this section were removed later. They are
> retained only to show the sequence of failed and revised decisions. The
> authoritative current design is in the data dictionary and Logs 0002 onward.

The default panel is now `research_core`:

- 12 value-weighted daily French industry research portfolios;
- 2-, 5-, and 10-year duration-convexity Treasury return proxies;
- Cboe VIX and SKEW;
- official U.S. Treasury 2-, 5-, and 10-year par yields plus the derived 10y–2y
  slope;
- New York Fed EFFR; and
- OFR FSI components stored only as external validation labels.

VVIX is downloaded and stored as an optional diagnostic because its shorter
history would otherwise remove the dot-com period from the model panel.

## Why OFR is validation-only

OFR FSI includes credit, equity-valuation, funding, safe-asset, and volatility
components that overlap the target returns and option-implied context. Treating it
as an ordinary predictor could build the desired stress label back into the model.
It is therefore retained for ex-post regime interpretation and stress-validation
tests, but excluded from `model_matrix.parquet`.

## Honest labels

- French industry portfolios are retrospective research portfolios, not investable
  ETFs.
- Treasury target columns are approximate return proxies derived from par yields,
  not observed bond total returns.
- Cboe and French raw data are downloaded locally and never redistributed.
- A publication-grade applied panel requires licensed point-in-time total returns.

## Limitations recorded in that pass — superseded

1. French portfolio histories are periodically reconstructed and are not a
   point-in-time security database.
2. The Treasury proxy uses a transparent duration-convexity approximation and
   should be replaced by licensed bond total-return indices for applied claims.
3. Current direct histories can be revised; snapshots and hashes make the run
   auditable but do not reconstruct every historical vintage.
4. The fixed train/validation/test split is only the Phase 0 smoke test. Modeling
   stages will use purged rolling origins and leave-one-crisis-out evaluation.
5. Availability assumptions are encoded at business-day resolution. Intraday
   policy-surprise research will require event timestamps, not daily joins.

## Go/no-go decision from that pass — superseded

**Go to Stage 0 baselines.** The data layer is adequate for testing the risk engine,
historical simulation, block bootstrap, multivariate Student-\(t\), and initial
factor/regime diagnostics. It is not yet adequate for investability, live-trading,
or real-policy causal claims.
